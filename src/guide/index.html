Macronic · Beginner’s guide · Updated 16 September 2026

From two texts to a bilingual reader

Macronic takes an English text and an existing translation, works out which parts correspond, and uses those correspondences to introduce another language as you read. The saved result contains both texts, the links between them, and the evidence for the substitutions.

You do not need to return to Codex for every text. Once the preparation software is installed on your computer, you can open its local upload page and prepare texts there. Codex can help install it, improve it, troubleshoot it, and prepare batches for you.

A static site serves files that your browser can display and run. A worker is a separate program that performs the heavier preparation. JSON is a structured text-file format for storing the results; it is not a model or a special kind of translation.

GitHub Pages remains a possible public hosting route, behind the existing release review. The test link you have been using is privately hosted with Sites. Neither host currently supplies an online Python worker.

The everyday workflow

  1. Find two matching texts. Start with the same chapter in English and French. Save each as UTF-8 plain text (.txt), with paragraph breaks. Record the edition and translator, or “Unknown”. This tool does not create a translation. It does not yet clean PDFs, OCR or whole-book front matter for you.
  2. Start the local app. Open a terminal in the project folder, activate the installed Python environment, and run python -m pipeline.worker --projects corpus. Leave that terminal open. Open http://127.0.0.1:8765/ in your browser on the same computer.
  3. Upload both files. Enter the title, editions and source details. Click Create project. You can instead choose “Save sources only” if the models are not installed yet. Files are saved locally, not sent to a hosted model API.
  4. Review the result. When preparation finishes, use Open review workshop. Sentence groups may contain several sentences, or an unmatched side. Those are alignment units. The reader combines them into longer sections so you can learn from context.
  5. Correct and save. The workshop already lets you approve or reject links, select words to correct a link, and approve or exclude whole sentences. Supply your name and a reason. Changes initially live only in that browser tab. Use Export corrections before closing it.
  6. Keep the editable project up to date. Import the downloaded corrections into the saved project with the command below. This validates them and rebuilds its reader. A previous corrections file is retained. If you alter sentence-group boundaries, affected substitutions remain blocked until recomputed; automated boundary recomputation for these new projects is a later step.
  7. Export and test. Export reading file makes a smaller JSON file for the reader. “Open a reading file” expects this prepared JSON, not your original .txt files. Save both corrections and reading exports. Download saved project backup on the local app backs up what is already saved to disk; it cannot include unsaved edits in another tab.
  8. Add it to the corpus. Keep a backup, then ask Codex to help review and commit the project’s sources, evidence and amendments to GitHub. This is an explicit step. Over time these projects form the corpus for a later consumer-facing phone app.
node scripts/project.mjs export corpus/PROJECT_ID /path/to/downloaded-corrections.json

First-time setup

The reader and workshop do not need the models. Preparing new texts does. The preparation environment needs Node 24, Python 3.12, several GB of disk and memory, and the pinned dependencies and models. Ask Codex to help with setup if these commands are unfamiliar. In a terminal opened in the downloaded GitHub project:

npm ci
python3.12 -m venv .venv
# macOS / Linux:
. .venv/bin/activate
# Windows PowerShell instead:
# .venv\Scripts\Activate.ps1
pip install --extra-index-url https://download.pytorch.org/whl/cpu -r pipeline/project-requirements.lock.txt
python -m pipeline.download_models
python -m pipeline.worker --projects corpus

Model downloading needs an internet connection. Preparation then uses the cached, pinned models. Keep the environment active when you start the worker. Closing the terminal stops the service. A stopped preparation is marked as failed on restart; its sources remain saved. You can retry with python -m pipeline.project run corpus/PROJECT_ID.

The two-file command

The upload page calls the same preparation code as this command. You can use it directly, or ask Codex to run it in a suitable environment:

python -m pipeline.project create english.txt french.txt --output corpus/my-book --title "My book, chapter 1" --english-edition "Edition or Unknown" --target-edition "Edition or Unknown" --target-language fr

Add --sources-only to save and check the inputs without running models. Later use python -m pipeline.project run corpus/my-book. A completed project is never silently overwritten. Use a new folder for a fresh model run.

What works now, and what comes later?

Now: English/French preparation code, a local upload interface, editable browser alignment review, correction exports, reading exports, six levels, and longer reading sections. Chapters II–IV have now been prepared with the pinned Bertalign and SimAlign models. The reader contains Chapters I–IV in 18 longer sections. Use the chapter menu to jump, or Next to continue across chapters; jumping does not count skipped sections towards gradual progression.

The reader starts at A little French (or the loaded learning language). With gradual progression enabled, English lasts 3 sections, A little lasts 4, More lasts 5, and Even more lasts 6. It stops at So much; full French is your choice. Going back does not count a section twice. Changing the level or toggling progression restarts the interval for that level.

New texts use the existing limited dictionary subset. Their word substitutions may therefore be sparse. Uncertain words stay English. Candide’s individually checked adjectives and whole sentence are not copied into new works. You can add reviewed decisions in the workshop.

Later: a broader lexical evidence collection, validated Yiddish preparation, simpler project saving and boundary recomputation, and the consumer-facing phone app. Yiddish labels and right-to-left display already work, but reliable preparation is a separate task. The future phone app will consume the reading exports without needing the preparation models.

This guide is kept with the app’s code and should be updated whenever the workflow changes. The source of truth for your work is the saved project and its version history, rather than the conversation with Codex.
